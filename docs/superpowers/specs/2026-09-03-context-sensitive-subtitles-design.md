# Context-Sensitive Multi-Tier Subtitle Architecture

**Date:** 2026-09-03  
**Status:** Validated Design  
**Author:** Pair Programming Assistant (Antigravity) & System Lead  

---

## 1. Executive Summary & Goals

### 1.1 Problem Statement
The current subtitle implementation in CastCast has significant limitations:
1. **Hardcoded English Lock:** Subtitle requests are hardcoded to `"eng"`.
2. **Brittle Hash Lookup:** External lookups depend solely on OpenSubtitles' 64-bit `moviehash` on the first/last 64 KiB of a local file, which fails on transcoded files, non-scene releases, and all web streams.
3. **Ignored Local Subtitles:** Local media files with multiple embedded languages or foreign-language sidecars (`.es.srt`, `.ja.vtt`) only have their first English track processed, discarding all other local languages.
4. **Context Blindness:** The UI subtitle button disables itself on YouTube, ignores Amazon Prime Video's built-in DASH subtitle streams, and forces a disruptive media re-cast whenever an OpenSubtitles track is fetched.
5. **4K Vulnerability:** Any mechanism that resorts to video re-encoding or burning subtitles ruins 4K UHD, HDR10, and Dolby Vision throughput on portable hardware.

### 1.2 System Goals
* **Exhaustive Local Scavenging (Tier 1):** Before reaching out to the network, exhaustively discover and convert all local subtitles (embedded container streams in any language + directory sidecars matching the video's basename).
* **Pre-Flight Ingestion & Instant Switching:** Register all scavenged local tracks into the Chromecast `LOAD` payload (`MediaInformation.tracks`) at playback start. Enable instant, zero-rebuffer track switching or disabling via `EDIT_TRACKS_INFO`.
* **Context-Sensitive Remote Ingestion (Tier 2):** When local subtitles are absent or when a user requests an additional remote language:
  * **Amazon Prime Video:** Directly extract and activate multi-language subtitle tracks from the Amazon DASH manifest / playback envelope with 100% Widevine DRM 4K UHD preservation.
  * **YouTube:** Query `yt-dlp` for available tracks categorized into Creator/Manual (`manual`), Autogenerated (`(autogenerated)`), and Translated (`(translated)`).
  * **Local Media / Other:** Query modern subtitle REST APIs (SubDL with OpenSubtitles fallback) by TMDB/IMDb ID and title.
* **4K UHD Preservation:** Strictly deliver all subtitles out-of-band as WebVTT sidecars or DASH text adaptation sets. Zero video re-encoding, zero hardsubbing.
* **Context-Sensitive UI Drawer:** Provide a sleek, accessible slide-over drawer allowing language selection, track toggling, and source-aware status.

### 1.3 Non-Goals
* Hardcoded pixel-burning (`ffmpeg -vf subtitles=...`), which degrades 4K HDR playback.
* OCR extraction of bitmap subtitles (VobSub/PGS). Bitmap tracks will be flagged as unsupported sidecars in favor of text-based formats (SRT/VTT/ASS).

## 3. Subsystem Specifications

### 3.1 Tier 1: Local Subtitle Scavenger (`daemon/castcast/service.py`)

#### A. Embedded Stream Harvesting
* Inspect `probe_info["subtitles"]` for all streams where `codec_type == "subtitle"`.
* Supported text subtitle codecs: `subrip` (SRT), `ass`, `ssa`, `webvtt`, `mov_text`.
* For each stream:
  * Extract stream language tag (ISO 639-2 / 639-1) or fall back to `"und"` (undefined).
  * Extract stream title / label (e.g., `"SDH"`, `"Commentary"`, `"Director's Notes"`).
  * Convert to WebVTT using `ffmpeg -hide_banner -y -i <path> -map 0:s:<idx> -f webvtt <work_dir>/<hash>_<idx>.vtt`.
  * Cache the output based on source file modification timestamp.

#### B. Directory Sidecar Harvesting
* Scan the video's parent directory for files matching `<stem>.*.<ext>` or `<stem>.<ext>`, where `<ext>` is `.vtt`, `.srt`, `.ass`, `.ssa`, or `.sub`.
* Parse language tags from the filename (e.g. `Movie.2024.en.srt` -> `en`, `Movie.2024.spanish.vtt` -> `es`).
* If not already `.vtt`, convert to clean WebVTT via `ffmpeg`.
* Deduplicate identical tracks (matching language + timing).

#### C. Chromecast Pre-Flight Registration
* Build the `MediaInformation.tracks` array:
  ```json
  [
    {
      "trackId": 1,
      "type": "TEXT",
      "trackContentId": "http://192.168.1.50:8765/subtitles/embedded_0.vtt",
      "trackContentType": "text/vtt",
      "name": "English [Embedded]",
      "language": "eng",
      "subtype": "SUBTITLES"
    },
    {
      "trackId": 2,
      "type": "TEXT",
      "trackContentId": "http://192.168.1.50:8765/subtitles/sidecar_es.vtt",
      "trackContentType": "text/vtt",
      "name": "Spanish [Sidecar]",
      "language": "spa",
      "subtype": "SUBTITLES"
    }
  ]
  ```
* Default activation:
  * Activate `[1]` if an English track is found.
  * If no English track is found, default to `[]` (off) or the first native track.

### 3.2 Tier 2: Source-Specific Remote Fallback

#### A. Amazon Prime Video (Widevine DRM 4K UHD)
* **Zero Video Mutation:** Do not touch video representations in the MPD manifest.
* **Manifest Parsing:**
  * Parse `<AdaptationSet contentType="text">` or `mimeType="text/vtt"` / `application/ttml+xml`.
  * Extract language codes and role labels (e.g., `main`, `dub`, `description`).
* **Track Activation:**
  * Since Shaka Player inside the CAF receiver natively parses these tracks from the manifest, switching subtitle language simply sends `EDIT_TRACKS_INFO` with the corresponding Shaka text track ID.

#### B. YouTube (`yt-dlp`)
* **Metadata Extraction:** Execute `yt-dlp --dump-json --skip-download <url>`.
* **Categorization:**
  1. `subtitles`: Creator / Manual uploads -> Label: `<Language> (Manual)`.
  2. `automatic_captions`:
     * Speech-to-text -> Label: `<Language> (autogenerated)`.
     * Translations -> Label: `<Language> (translated)`.
* **Download & Sideload:**
  * Download only the selected `.vtt` file to the work directory.
  * Register the track with the active cast session.

#### C. Local Media / External Fallback (SubDL + OpenSubtitles)
* Triggered when local scavenging yields 0 tracks or user searches for an uncatalogued language.
* **SubDL Client:**
  * Uses the TMDB ID / IMDb ID already enriched by `TMDBClient`.
  * Calls `https://api.subdl.com/api/v1/subtitles?imdb_id=<id>&languages=<lang>`.
  * Downloads and unpacks `.srt`/`.zip`, converts to `.vtt`.
* **OpenSubtitles Fallback:**
  * If SubDL is unconfigured or returns empty, query OpenSubtitles REST API v1 using title query and movie hash.

### 3.3 API Contract Updates (`daemon/castcast/api.py`)

1. **`GET /subtitles/available?path=<path>`**
   * Returns list of currently registered tracks, plus remote search availability:
   ```json
   {
     "source_type": "local" | "amazon" | "youtube",
     "active_track_ids": [1],
     "tracks": [
       {"track_id": 1, "language": "eng", "label": "English [Embedded]", "source": "embedded"},
       {"track_id": 2, "language": "spa", "label": "Spanish [Sidecar]", "source": "sidecar"}
     ],
     "remote_supported": true
   }
   ```

2. **`POST /subtitles/select`**
   * Body: `{"track_id": 1}` or `{"track_id": null}` (to disable).
   * Executes `EDIT_TRACKS_INFO` directly on the supervisor without reloading media.

3. **`POST /subtitles/fetch_remote`**
   * Body: `{"path": "<path>", "language": "spa", "type": "manual" | "auto" | "translated"}`
   * Downloads selected remote subtitle, mounts it as WebVTT, and activates it.

### 3.4 Frontend UI Specification (`src/app/App.tsx`)

1. **Subtitles Button State:**
   * When subtitles are active: Green highlighted button displaying current language code (e.g., `[Subtitles: EN]`).
   * When subtitles are off: Standard border button displaying `[Subtitles: Off]`.
   * Tapping opens the **Subtitles Drawer**.

2. **Subtitles Drawer Modal:**
   * **Source Badge:** Displays current playback mode:
     * `[Amazon 4K UHD]`
     * `[YouTube Stream]`
     * `[Local Media (4K)]`
   * **Instant Toggle:** Top button to `Turn Subtitles Off`.
   * **Local / Built-in Tracks List:** Shows all scavenged tracks with instant 0ms switching.
   * **Remote Fetch Section:**
     * For YouTube: Organized into tabs/accordions: *Manual*, *Auto-generated*, *Translated*.
     * For Amazon: Lists all manifest language streams.
     * For Local: Search remote subtitle repository by language dropdown.

## 4. 4K UHD & Hardware Compatibility Assurance

| Risk | Mitigation |
| :--- | :--- |
| **Accidental 1080p fallback** | Never use `ffmpeg -vf subtitles=...`. Subtitles are strictly transported as WebVTT sidecars over HTTP. Video stream is kept in `copy` mode. |
| **Widevine 4K DRM breakage** | Amazon manifest proxy preserves all 4K UHD Representation sets and DRM signaling. Subtitles are switched via native DASH adaptation sets or overlay. |
| **Playback stutter on subtitle change** | Because local tracks are pre-registered on initial `LOAD`, switching languages issues `EDIT_TRACKS_INFO`, eliminating video buffering or timestamp drift. |
